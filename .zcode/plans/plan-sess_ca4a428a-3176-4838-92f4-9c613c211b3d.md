# Rencana: Kolom Baru "Realisasi Pegawai + Lampiran" di Bagian PERILAKU KERJA (SKP Dosen Kualitatif)

## Tujuan
Menambah 1 kolom baru di tabel PERILAKU KERJA, sejajar dengan kolom UMPAN BALIK & HASIL KERJA. Isinya: **teks + file (bisa banyak)** yang diisi **pegawai** lalu dikirim ke **Dekan**. Dekan hanya bisa **melihat teks (read-only) & download file**, tidak bisa edit. Hanya baris yang ditandai **"Wajib Lampiran"** oleh Super Admin yang menampilkan input aktif; baris lain tetap muncul tapi **dimatikan (disabled)**.

## Keputusan (sudah dikonfirmasi)
- **Penanda "wajib lampiran"**: Toggle di halaman acuan Super Admin (per aspek perilaku), disalin ke baris perilaku saat SKP dibuat.
- **Pola input**: Banyak baris, tiap baris = 1 teks + 1 file (ikut persis pola UTAMA1 yang sudah jalan). Pegawai tekan "Tambah" untuk banyak file.
- **Setelah kirim**: Kunci permanen (pakai `$isRealisasiSaved` yang sudah ada).
- **Penyimpanan file/teks**: Pakai ulang tabel `skp_kualitatif_realisasis` dengan `target_type='perilaku'` + `target_id = id baris perilaku`. **Tidak bikin tabel baru.**
- **Tidak menyentuh perhitungan RATING/PREDIKAT** — kolom baru murni bukti pegawai, tidak ikut dihitung. Aman untuk `RekapSkpController`.

## Data Model Baru
| Tabel | Kolom baru | Tipe | Default | Alasan |
|---|---|---|---|---|
| `skp_kualitatif_acuan_parents` | `butuh_lampiran` | boolean | false | Toggle Super Admin per aspek |
| `skp_kualitatif_perilakus` | `butuh_lampiran` | boolean | false | Flag aktif per baris SKP (disalin dari acuan saat SKP dibuat) |

### 8. Tidak diubah
- `RekapSkpController` — kolom baru tidak ikut perhitungan predikat (sudah diverifikasi).
- `EvaluasiBawahanController::verifyKualitatif` — tidak menyentuh `realisasis` perilaku (yang diupdate hanya `hasil_kerja` & `umpan_balik` per item).
- `SkpKualitatifRealisasi` model — sudah punya field yang dipakai (`target_id`, `target_type`, `realisasi`, `bukti_dukung_*`). `getTarget()` sudah handle `target_type='perilaku'`? Cek: method `getTarget()` handle 'utama'/'jabatan'→SkpKualitatif, 'tambahan'→SkpKualitatifTugasTambahan. **Perlu tambah** `elseif ($this->target_type === 'perilaku') return SkpKualitatifPerilaku::find($this->target_id);` di model ini.

### 9. Backfill data lama (opsional, dijalankan terpisah)
SKP yang sudah dibuat sebelum migration tidak punya `butuh_lampiran` (default false) → kolom perilaku di SKP lama tidak akan aktif. Bisa di-backfill via tinker: untuk setiap `SkpKualitatifPerilaku`, cari acuan parent yang `sasaran_kinerja`-nya cocok & `kategori='perilaku'`, copy `butuh_lampiran`-nya. Saya akan jalankan **hanya jika Anda minta** setelah plan ini disetujui.

## Urutan Eksekusi (biar minim risiko)

2. Ubah model `SkpKualitatifPerilaku` (fillable) + `SkpKualitatifRealisasi` (`getTarget()`).
3. Ubah controller SuperAdmin `store()`/`update()` (copy flag).
4. Ubah view acuan (toggle).
5. Ubah view pegawai (input + kunci).
6. Ubah `storeRealisasi` (cabang perilaku).
7. Ubah view penilai (read-only + download).
8. Tes manual: buat SKP baru → cek toggle di acuan → cek kolom perilaku aktif di pegawai → upload file → login sebagai Dekan → cek read-only + download.
9. (Opsional) backfill SKP lama.

## Catatan Risiko
- Perilaku hapus-semua-insert-ulang di `storeRealisasi` tetap ada (tidak diubah di plan ini). Jika Anda mau saya bungkus dengan DB transaction, bisa ditambah — tapi di luar scope permintaan awal.
- SKP lama: `butuh_lampiran` default false → kolom perilaku tidak aktif sampai di-backfill. Ini sudah dijelaskan di poin 9.
- Tidak ada perubahan arsitektur besar — semua mengikuti pola yang sudah teruji (utama1 realisasi + acuan toggle generik).
